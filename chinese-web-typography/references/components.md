# 组件文字策略

| 场景 | 优先策略 | 实际检查 |
| --- | --- | --- |
| 展示型标题 | 给内容合理宽度，局部试用 balance；必要时做可回退的语义分组 | 长短标题、窄屏、文字放大时是否自然；不只检查参考截图的宽度 |
| 文章正文/引用 | 自然换行，限制过长行宽，无单位行高，区分段落与换行 | 中文标点、英文长词、链接、引用原文、繁体与生僻字 |
| 商品/信息卡片 | 内容区 `min-inline-size: 0`，标题允许增长 | 最长名称、不同描述长度、价格单位、操作入口是否仍可见 |
| 导航/标签/徽标 | 允许布局重排，优先保留可理解的标签 | 不将无限长度标签全部 nowrap；不把长导航简单压小字 |
| 按钮 | 用内边距和最小高度，不依赖固定高度；可多行或调整布局 | 长操作文案、提交中/失败状态、文字放大、行内图标对齐 |
| 表单 | 可增长标签与帮助/错误文本，字段有稳定可读尺寸 | 不把 placeholder 当唯一标签；完整错误不做省略；长输入可在控件内滚动 |
| 表格/后台数据 | 区分可折行说明、完整标识符、对齐数字；必要时局部横向滚动 | 最大数值、缺失值、很长公司名与订单号、键盘能访问滚动区 |
| 弹窗/通知 | 高度适应内容，窄屏和矮屏时内容区可滚动 | 长错误、操作按钮、文字放大后是否还能读完并关闭 |
| 代码/URL | 按使用目的选局部滚动或应急折行，复制不改变内容 | 禁止批量插入空格；保留 code/pre 原本有意义的空白 |

## 常见布局修复

先找最小宽度限制的实际来源。flex/grid 子项的默认最小尺寸可能阻止收缩；常用的局部修复是 `min-inline-size: 0`，网格的弹性列可用 `minmax(0, 1fr)`。这不能替代内容本身的断行策略，也不应给所有元素无差别覆盖。

固定高度与 `overflow: hidden` 是截断来源。标题、提示与按钮优先随内容增长；确实需要摘要截断时，用展开按钮、详情页等提供完整文本。单独的 `title` tooltip 不能满足触屏和键盘阅读完整内容的需求。

中文排版修复不自动包含整个组件的无障碍审计。仍需处理因本次文字变化产生的阅读顺序、缩放、标签与操作可达问题；未测屏幕阅读器就不要声称全面无障碍合规。
