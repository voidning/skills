# 中文网页排版

让真实中文内容在实际布局中读得顺、看得全，并适应内容长度与屏幕变化。保留用户文案、事实、品牌风格和项目已有设计系统；不要为了排版擅自改写合同、引用、金额、名称或用户输入。

## 工作方法

1. **识别内容与约束。** 确认简繁体及地区习惯、正文/标题/控件/数据的角色、现有字体与布局、内容是否动态。优先从项目推断，不把普通实现选择变成追问。只有截图时给出假设，拿到 DOM/CSS 或渲染证据后才确定原因。
2. **选择最小适用规则。** 中文断行、字体、标点和混排读取 [文字规则](references/text-rules.md)；卡片、表单、表格等读取 [组件策略](references/components.md)。无需为一个标题加载全部细节。
3. **按原因修复。** 先查硬换行、不换行片段、容器宽度、flex/grid 的最小尺寸、固定高度和溢出，再调整字号、行距或局部断行。优先修复容器约束，不靠隐藏溢出或缩小到难以阅读来消除症状。
4. **用真实长度验证。** 按 [渲染验收](references/verification.md) 选择适用的常规与边界数据，检查真实浏览器的排版。需要可复用样例时读取 [案例集](references/cases.md)，不要把样例的风格或像素值作为通用要求。
5. **报告证据。** 简述修改原因、测试内容/宽度/浏览器与仍未验证的部分。不能仅凭 CSS 正确、构建通过或截图存在就声称可读性、所有浏览器或无障碍已通过。

## 必须守住的边界

- 文字不能意外重叠、消失或被裁切；关键说明与错误信息必须可见。截断须有适合触屏和键盘的完整信息入口。
- 普通内容应适应窄屏与文字放大；宽表格/代码等可局部滚动，但不能把整页撑宽。不要用全局 `overflow-x: hidden` 掩盖问题。
- 不批量向正文、代码、URL、标识符或用户输入插入空格、不换行空格、零宽字符。复制后的内容应保真。
- 不全局套用 `word-break: break-all`、`keep-all`、`white-space: nowrap` 或强制两端对齐。规则必须有组件和内容边界。
- 标题自然语义优先；不要仅为制造短行和留白插入 `<br>`。诗歌、地址、用户明确要求的艺术分行等可以保留有意义的换行。
- 不能承诺自动消除所有孤字或保证浏览器理解中文词义。先修明显影响阅读的问题，避免为消除一个孤字锁死所有宽度。

## 默认策略与判断空间

- 使用准确的 `lang`，如 `zh-CN`、`zh-TW`；语言属性帮助字体选择、断行和辅助技术，但不是中文分词器。局部不同语言按需标记，不必逐个英文品牌加标签。
- 正文优先自然换行、起始侧对齐；行长、字号、行高根据页面密度、字体和读者调整，不规定全站统一数值。
- 短标题先尝试更合适的可用宽度与字号。`text-wrap: balance` 只作为局部增强；它平衡行长，不保证按语义分组。`pretty` 同样不能替代人工验收。
- 数值格式、简繁体标点及中英间距遵循项目的地区规范并保持一致；不要把个人排版偏好写成语言的唯一标准。
- 对未列出的情况，依次判断内容是否完整、阅读是否顺畅、层级是否清楚、内容变化是否稳健，再选择最小改动。不要扩大为整站重构或文案重写。
