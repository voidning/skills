# AI 轻科普系列

面向对 AI 感兴趣、但不一定懂代码的中文读者。用生活例子把机制讲准，保留技术含量；像跟朋友解释，避免说明书腔、强行情绪和夸张宣传。

这是普通文件技能包，可由不同模型和 agent 阅读。相对路径以本文件所在目录为基准；不要求 Codex、Claude Code、特定模型、插件或专有工具。`agents/openai.yaml` 仅是可选客户端元数据。

## 每期开始

1. 复用当前对话中已确认的主题、受众、媒介、风格和文案，不重复询问。只问会改变方向或造成大返工的缺失信息。
2. 首次使用本包，查看 [参考封面](assets/reference-cover.png) 和 [参考视频](assets/reference-video.mp4)。无法播放时可提取帧了解风格，但不把帧检查当作实播试听。
3. 阅读 [视觉规范](references/visual-system.md)。制作成套内容或发布文案时，阅读 [制作与交付](references/production.md)。
4. 对新模型、产品、版本、热度、价格和性能等事实查当前官方原始资料；区分官方宣称、独立证据、实际测试和概念演示。没有查证工具时说明待核实项，不能编造来源或实测。

## 内容原则

- 生活问题是解释入口，不可为了通俗而讲错机制。先写出本期最重要的一句技术结论，再选一个能准确支撑它的例子。
- 推荐骨架：日常问题 → 核心机制 → 看得见的过程 → 能力边界 → 简短用途提问。按选题调整，不强制每期做左右对比或复刻 Jev 分镜。
- 同条件比较才有解释力。把输入、预设选项、模型返回值和程序执行的动作区分清楚。
- 不虚构“我试了100次”“熬夜两天”“翻车后发现”等经历；可以真实地说“我把公开资料画成了动画”。示意概率、示例回答、编排游戏必须在对应画面就近标注“概念演示，非实际模型输出”。
- 文案自然、简短、口语化。保留“决策”等有用技术词，用生活例子解释它，不强行换成“哑巴机器人”“算命”等标签。
- 封面直接表达主题。默认标题如“Agent 是怎么干活的？”；“外网爆火”只在该期有可记录的传播证据时使用，不能继承参考封面的热度判断。不默认加“到底”“震惊”等词。
- 结尾短且贴题。用途类例子：“你觉得 Jev 能用来干啥？”不要虚构输出引战，不强迫观众提供复杂案例，不把本句机械套进所有选题。
- 只借用抽象视觉特征。不加入 Claude / Claude Code 名称、星芒、吉祥物、产品标志或界面品牌元素。若新选题本身就是该产品，以用户明确的内容要求为准。

## 图文与视频

- 按用户指定范围制作。只要求图文就不自动追加视频；明确要成套，才准备两套。
- 图文方便停留和回看：通常每页一个问题，保留足够解释和必要边界；页数由内容决定。
- 视频展示过程：让文本生成、连线、分支、概率和状态真正变化，不把图文逐张做成静态幻灯片。字幕不需要同时承载图文版全部解释。
- 两版分别完整、分别写发布文案。统一题材和视觉，但不能只把同一段文字重复贴两次。

## 复用工程

[参考工程](assets/reference-project/render.py) 可重现本期样式、打字、概率条、像素动作和轻音效。它是 **Jev 专用的已完成示例，不是输入任意主题即可生成成片的通用引擎**。

复制工程到本期工作目录再修改，禁止直接覆盖技能内参考。按选题重写文案、分镜和动态组件。Agent 结构可以改为“模型 → 工具 → 结果 → 模型”循环，不沿用 Jev 的三选一逻辑。可以改用其他渲染技术，只要达到同样的视觉和可编辑性。

## 验证与交付

- 实际渲染后看目标尺寸和手机缩略图；检查字体、遮挡、阅读时间、连线方向、选项/概率/动作对应。
- 视频完整解码并检查音轨；有条件时实际播放试听。准确区分帧检查、音频信号检查、实际试听和未验证项。
- 只在当前环境允许且适合时调用独立验收；环境禁止子代理就不调用，也不把自检冒称独立验收。修复已确认缺陷后，仅复验受影响部分。
- 新系列或大幅改风格可先出小样；已经认可的风格直接复用。只有明确约定需要确认的节点才等待，不对每期重复索取同一批准。
- 交付已完成文件、可编辑源文件、必要来源和未验证项。素材准备不包含登录、上传、发帖、首评或置顶；这些需要独立授权。
