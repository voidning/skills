# 制作

用于网站、应用、游戏、交互原型。先检查已有工程、运行方式与相关规则，明确是新建、复用还是修改；现有项目的改动同时读修改模块。

- 用一句可操作的体验描述锁定首版，例如“进入→移动战斗→成长选择→结算→重开”。确定用户、使用环境和最终交付形式，不让未来功能淹没首版。
- 技术选型依据既有工程和实际需求；只在必要时加载对应专业 Skill。入口不强制任何框架、托管商、模型或多代理体系。
- 新视觉不确定时转视觉模块先出代表性小样。新交互或能力有风险时先验证关键路径；验证不等于提前完成全套系统。
- 保留被认可的内容与实现。明确已授权制作完整首版时，常规敌人、拾取、重开等组成部分不逐项再问；新增重大玩法或平台变更则说明影响。
- 按正常操作完成核心流程，检查关键失败状态与恢复。游戏要实际玩核心循环，网页要检查实际布局与交互；编译通过或脚本运行成功不能代替体验验收，也不能证明“好玩”。
- 完成后交付可使用成果、运行入口及必要源文件，说明实际检查与剩余限制。依赖不可用或能力不足时给证据及影响，不把静态假数据演示叫完整实装。

只制作并不包含上传、部署、发帖或售卖；已有明确授权覆盖这些动作时正常继续，不重复确认。
