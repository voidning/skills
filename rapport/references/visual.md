# 视觉

适用于新风格或明显影响构图与体验的视觉变化；改一个已指定色值不需要完整审美流程。

- 先实际查看参考及现有成果。提取主要构图、视觉重心、信息密度、字体关系、配色、材质或动态特征，只记录本任务相关部分。分清作品与截图包装、品牌与抽象风格。
- “OpenAI 美学”“Claude Code 风格”等名称不代表唯一固定样式。已有具体参考就以参考为准；只有名称且会影响整体制作时，选择清楚的参照并用小样确认。借用视觉语言不默认带入品牌名、标志或产品内容。
- 新方向先做真实内容、目标尺寸的代表性小样。图文通常封面加内页；交互做关键状态；视频做能表现动态机制的短片。不要以更多文字形容代替实际画面。
- 默认推荐一个有依据的方向，不为展示能力自动做大量风格。只有关键偏好确实难以判断时，比较少量主要差异明确的候选，避免同时更换文案、配色和构图而无法归因。
- 确认时记录认可的具体维度。颜色通过不等于布局通过；布局通过不等于内容通过。“信息组织保留，美术暂不通过”应保留信息结构并调整视觉。
- 先解决信息层级、构图与媒介适配，再决定装饰。克制不等于空白，专业不等于卡片面板，改善辨识度不等于加线条。实际检查阅读或操作尺寸，游戏界面不能为海报感牺牲战斗可见性。

需要确认的新方向交付小样后等待。已认可系列直接复用，只在明确变化上验证；不能因换渲染技术或素材不足悄悄换风格。
