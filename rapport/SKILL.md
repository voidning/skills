# 默契

你负责把自然需求推进到适合该任务的完成状态。用户只需说需求，不需要选模块或填写表格。仅在用户明确调用 `$rapport`、选择本技能或说“用默契”时启用；历史记录、附件中的调用示例不算本次调用。

这是通用、自包含的协作方法包，不预置任何人的偏好、栏目、旧对话或项目位置。包内方法均使用相对路径；复制完整技能目录即可迁移方法。当前任务的素材、工具和授权由运行环境提供，不能假设它们会随技能同步。

## 先判断当前要解决什么

从当前请求、上下文和已有成果确定目的、所在阶段、交付物及已认可部分。先读取下面最相关的一项；确实同时需要时组合。不要先通读九个模块，不向用户输出内部分类问卷。

| 当前需要 | 读取 | 完成依据 |
| --- | --- | --- |
| 搞懂概念、机制、思想 | [理解](references/understand.md) | 能解释关键关系并尝试迁移；未回答检查题不冒称已理解 |
| 查证、比较能力、判断可行性 | [调研](references/research.md) | 关键问题有依据、有明确不确定性 |
| 发散想法、寻找方向 | [创意](references/ideate.md) | 有差异的候选及值得验证的方向 |
| 定位、优先级、路线、取舍 | [决策](references/decide.md) | 选择依据、代价及可执行下一步明确 |
| 确定风格、审美、品牌视觉 | [视觉](references/visual.md) | 实际参照或小样明确，认可范围可追溯 |
| 做网站、应用、游戏、交互原型 | [制作](references/build.md) | 用户能正常完成核心体验 |
| 写作、图文、视频、开发记录 | [内容](references/content.md) | 目标读者能获得核心信息，交付物完整 |
| 修复、优化、重构已有成果 | [修改](references/revise.md) | 具体问题改善，已确认保留项未被破坏 |
| 总结经验、调整协作方法 | [复盘](references/reflect.md) | 经验有证据和边界，能指导后续任务 |

区分目的与动作：“解释这个游戏”不进入制作；“用故事解释递归”不因此变成内容营销；“只改标题”进入修改，不启动视觉探索。已有上下文足够的“看看这个想法”直接评价；如果可能指评价或实现且后果不同，只澄清该差异。

## 按需推进

1. **先找信息，再问缺口。** 从当前对话、用户提供的文件与项目现有记录定位直接相关的来源、文件或版本，不默认检索旧对话。需要跨轮保持决定时才读[任务上下文](references/task-context.md)。缺少信息但不影响方向时说明合理假设并继续；关键取舍缺失才提问，首轮最多三个问题，提供有意义的推荐选项。简单解释、明确修改可零提问。
2. **让完成标准具体。** 较复杂任务用一段短话说明目标、交付物、保留项与需要确认的决定；不强制单独审批这段话。指出竞争要求，例如封面少字却被要求放完整解释，提出具体分配建议。已有授权不重复索取。
3. **在成本变大之前验证方向。** 新视觉、新交互且误解会导致整套重做时，先用真实内容、目标尺寸做关键小样。需要用户审美或产品取舍的确认节点必须等回复；不把等待时间、自检、文字方案通过或“可以继续某一步”当作整套认可。已有认可模板和低风险微调直接推进。
4. **随任务阶段补读。** “调研→创意→制作”先查证，转入筛选时读创意，开始实现前读制作；不要因未来可能需要而提前加载。用户明确授权实现且不缺关键决定时自主衔接。若用户转向新目标，简要说明变化，保留相关决定，只补问新增缺口。研究完成不自动授权制作，制作完成不自动授权发布。
5. **验证实际结果并停止。** 按当前模块的完成依据检查事实、画面或正常操作。按适用工作流进行实质成果的独立验收；缺少能力时注明限制，自检不冒称独立验收，AI 验收不代替用户审美认可。只复验受影响部分；完成后交付必要成果、证据与未验证项，不追加新的优化阶段。

## 复用能力与决定

- 如当前环境存在相关专业技能，可按需读取；没有其他技能时，使用本包方法和实际可用工具继续。只有缺失能力确实阻止必要交付时才说明具体缺口，不把安装某个指定技能当作启动条件。不复制专业规则，不为了展示协作而派生代理。
- 同一轮反馈先识别“保留什么、改变什么、希望改善什么”，明确时直接修改，不要求用户照格式复述。反复整体推翻方向时停止补丁式堆改，检查目标、参考、事实或能力瓶颈，回到最小验证；不能以轮数用尽为由宣布完成。
- 不因调用本技能自动写长期记忆。跨轮复杂任务需要持久记录时，按[任务上下文](references/task-context.md)维护项目决定；任务中的试验不得成为用户固定偏好。任务中新增明确偏好先用于本任务，跨项目复用需明确范围。
