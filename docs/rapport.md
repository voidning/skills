# 默契（rapport）

一个通用、自包含的 AI 协作入口。用户自然描述需求，AI 根据当前目的与阶段读取相关方法，不需要手动选择多个技能。

## 安装与调用

安装到个人 Codex：

```bash
npx skills@latest add voidning/skills --skill rapport -a codex -g
```

安装后，在技能列表中选择「默契」，或明确调用：

```text
$rapport 用具体例子解释递归。
```

```text
$rapport 调研这个模型，找一个可行方向并制作演示。
```

```text
$rapport 保留这个页面的布局，只修改说明文案。
```

Codex 配置为 `allow_implicit_invocation: false`，普通聊天不自动启用。客户端需要重新加载技能列表时，可在新任务中查看。

## 按需工作

入口覆盖理解、调研、创意、决策、视觉、制作、内容、修改和复盘九个模块。先读取当前相关方法，随任务阶段补读，避免一开始加载全部内容。

已有信息足够就直接推进；缺少影响方向的决定时，首轮最多问三个关键问题。新视觉或新交互可能引起重大返工时先做实际小样，需要用户确认的节点等待明确回复；已认可部分继续保留。

专业技能与工具按环境能力选用，不强制安装指定的其他技能。完成标准随任务变化：学习重理解、调研重依据、制作看实际成果、修改看具体问题是否解决。

## 迁移与上下文

换电脑时重新安装，或从仓库复制完整的 [`rapport/`](../rapport/) 文件夹到目标环境的技能目录。保留入口、`references/` 和配置的相对位置。技能包不含个人档案、真实旧对话或某台电脑的绝对路径。

具体任务的素材、项目决定、账号连接和外部工具由新环境另行提供。技能不能恢复未带来的旧文件；看不到参考时应指出缺口，而不是猜测。

复杂任务优先复用项目已有决定记录；必要且允许写文件时，可以在项目的 `work/collaboration-decisions.md` 保存简短摘要。简单问答不创建台账，也不自动写入个人档案或改写全局规则。

## 检查与限制

开发测试位于 [`tests/rapport/`](../tests/rapport/)，包含匿名场景、夹具与[验收方法](../tests/rapport/acceptance.md)，不随技能安装。它们是维护用测试输入，不是用户记忆，也不代表所有行为已经通过实测。

规则和格式正确不能保证模型每次都遵循；客户端发现、跨客户端执行及长期减少返工的效果，需要在目标环境与真实任务中验证。其他客户端不一定识别 Codex 的界面和调用策略配置，应按该环境的技能支持方式使用。
